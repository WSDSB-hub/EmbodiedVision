# 04 - Serial Communication Protocol

## 目标
设计并实现上位机（PC/树莓派）与下位机（STM32）之间的串口通信协议，打通从AI决策到底层执行的指令传输链路。为后续视觉避障的远程控制奠定通信基础。

## 协议设计

### 帧格式
| 字节 | 内容 | 说明 |
|:---|:---|:---|
| 0 | 0xAA | 帧头，用于同步 |
| 1 | CMD | 指令码（0x01前进, 0x02后退, 0x03左转, 0x04右转, 0x05停止） |
| 2-3 | Left Speed | 左轮目标转速，int16，大端 |
| 4-5 | Right Speed | 右轮目标转速，int16，大端 |
| 6 | Checksum | 前6字节异或校验 |

### 指令示例
| 指令 | 帧内容 |
|:---|:---|
| 前进 100 RPM | `AA 01 00 64 00 64 C1` |
| 后退 100 RPM | `AA 02 FF 9C FF 9C 3B` |
| 停止 | `AA 05 00 00 00 00 05` |

## 实现状态
- **STM32端**：已实现串口接收中断回调 + 轮询解析代码（`03_Car_Serial/Core/Src/main.c`），支持单字符指令（'w'前进, 's'后退, 'a'左转, 'd'右转, 空格停止）
- **Python端**：已实现完整的指令打包、发送与协议自测脚本（`car_control.py`, `serial_self_test.py`）
- **协议验证**：Python端自测全部通过，证明打包/解析逻辑一致（见 `serial_protocol_test.png`）
- **联调状态**：因电脑串口占用问题暂时搁置，实际控制采用蓝牙单字符通信方案（已稳定运行）

## 关键问题与解决
1. **串口占用冲突**：Python脚本与SSCOM不能同时使用同一COM口。解决：测试时关闭SSCOM。
2. **联调失败**：多次尝试Python脚本发送指令无响应，但STM32端轮询接收代码逻辑已验证正确。最终采用蓝牙单字符指令替代，功能完全等价。
3. **协议设计价值**：即使联调未完成，帧格式设计、校验机制、打包解析逻辑已完整实现并通过纯软件自测，具备完整的通信协议设计能力。
